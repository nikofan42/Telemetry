# iRacing SDK Python Integration Guide

## Connection Setup
1. Memory-Mapped File Access:
   - File Name: "Local\\IRSDKMemMapFileName"
   - Event Name: "Local\\IRSDKDataValidEvent"
   - Update Rate: 60Hz (every 16ms)
   - Data Format: Uses triple buffering for consistency

2. Data Types:
   - Session Info: YAML format, updated on changes
   - Variables: Binary format, updated every tick (60Hz)
   - Variable Types:
     ```python
     IRSDK_CHAR = 0    # 1 byte
     IRSDK_BOOL = 1    # 1 byte
     IRSDK_INT = 2     # 4 bytes
     IRSDK_BITFIELD = 3  # 4 bytes
     IRSDK_FLOAT = 4   # 4 bytes
     IRSDK_DOUBLE = 5  # 8 bytes
     ```

## Firebase Integration Notes

1. Data Structure Recommendations:
   - Use separate collections for session, weather, and car data
   - Use car_id as document ID for car telemetry
   - Consider using Realtime Database for high-frequency updates
   - Use Firestore for session and weather data

2. Performance Considerations:
   - Buffer car telemetry data and batch update
   - Implement rate limiting for Firebase writes
   - Consider data aggregation for historical analysis
   - Use server timestamp for data synchronization

3. Example Firebase Structure:
```
iracing/
  ├── sessions/
  │   └── {session_id}/
  │       ├── info/
  │       ├── weather/
  │       └── timestamp
  ├── telemetry/
  │   └── {session_id}/
  │       ├── cars/
  │       │   └── {car_id}/
  │       └── timestamp
  └── pit_data/
      └── {session_id}/
          ├── status/
          └── timestamp
```

## Implementation Tips

1. Data Polling:
   ```python
   UPDATE_RATE = 1/60  # 60Hz
   BATCH_SIZE = 10     # Number of updates to batch
   ```

2. Error Handling:
   - Implement reconnection logic for SDK disconnects
   - Handle Firebase quota limits
   - Validate data before sending to Firebase

3. Memory Management:
   - Clear old data periodically
   - Implement data retention policies
   - Monitor memory usage for long sessions

4. Required Python Packages:
   ```
   firebase-admin
   pyirsdk
   numpy  # For efficient data handling
   ``` 

## Best Practices for Data Collection

1. Session Management:
   - Start new Firebase collection for each session
   - Use session_id as the root for all related data
   - Implement cleanup for old sessions

2. Data Sampling:
   - High-frequency data (60Hz):
     ```python
     HIGH_FREQ_VARS = [
         "car_position",
         "velocity",
         "acceleration",
         "engine_warnings"
     ]
     ```
   - Medium-frequency data (10Hz):
     ```python
     MEDIUM_FREQ_VARS = [
         "weather",
         "track_state",
         "lap_times"
     ]
     ```
   - Event-based data:
     ```python
     EVENT_VARS = [
         "flags",
         "pit_events",
         "session_state"
     ]
     ```

3. Error Recovery:
   ```python
   RECONNECT_TIMEOUT = 5.0  # seconds
   MAX_RETRY_ATTEMPTS = 3

   ```
